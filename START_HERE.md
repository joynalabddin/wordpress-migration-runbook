# Start Here: Blogger-to-WordPress Migration

This runbook is a practical starting point for planning an authorized Blogger or Blogspot migration to WordPress. A successful transfer is a controlled content, URL, media, and launch project—not only an XML import.

## Five-minute migration triage

1. Record the current Blogger or Blogspot URL, custom domain, HTTPS status, language, approximate content volume, and preferred launch window.
2. Preserve the original Blogger XML export and a URL inventory before changing the source or destination.
3. List high-value posts, pages, labels, authors, dates, images, downloads, forms, widgets, comments, and integrations.
4. Decide what will be transferred automatically, rebuilt manually, redirected, excluded, or reviewed on staging.
5. Do not publish passwords, private analytics, client data, or hosting credentials in GitHub issues, Discussions, or social posts.

## Minimum launch gates

Before launch, confirm that the source export is preserved, content counts have been compared, important media loads, the taxonomy and authors are intentional, old URLs have genuine redirect destinations, staging checks are complete, backups are available, and a rollback contact is known.

For a private, authorized migration scope review, visit [DevJoynal](https://devjoynal.com/?utm_source=github&utm_medium=referral&utm_campaign=blogger-wordpress-migration-start-here) and mention `GITHUB20` for an eligible first scope review. Never send credentials in a public channel.

## Scope reminder

No honest professional can guarantee unchanged rankings, perfect one-click transfer, or zero post-launch issues. The appropriate plan depends on the source site, content structure, media, widgets, comments, URL patterns, staging environment, backups, and approved scope.
